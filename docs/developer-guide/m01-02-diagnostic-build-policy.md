## Applicable policy and approval requirements

Current policy blocks unverified execution paths. The proposed rules clarification is not adopted and may not be relied upon. Independent review, an explicit versioned maintainer risk decision and separate approval of policy, publication and the exact workflow execution are prerequisites. The coordinator records the exact revision, environment, scope, costs, accepted risks, one-attempt budget and consumption. A push trigger cannot enforce this budget. A conflict with any binding requirement blocks the affected operation; no agent may resolve it by implication.

## Authorized environment

Only one fresh regular GitHub-hosted Windows x64 VM, candidate `windows-2025`, subject to confirmation of its identity, availability and zero cost before authorization. No personal host, larger runner, self-hosted runner, paid service or fallback. Tool versions and components must be verified before provisioning. No repository secrets, environment secrets, write-capable repository token or persisted checkout credentials. No shared dependency caches or additional actions.

## Required preconditions

Verify the exact source, sole parent, actual workflow revision, three-path diff, unchanged lockfile blobs, package manifests and trusted registry sources. Confirm free usage and maintainer/coordinator consumption control outside the workflow. Confirm Rust 1.100.0 for the Windows x64 MSVC target, Node 24.22.3 and npm 11.19.1, an initialized x64 MSVC C++ compiler and linker, and a Windows SDK with x64 headers and libraries. Use only the existing, exactly bound Windows x64 Node installation in the runner tool cache and its associated npm-cli.js; do not automatically install or select an alternative version. Record actual MSVC and SDK versions; the maintainer host's patch versions are not required. WebView2-related build dependencies are supplied through the locked dependency graph; the installed WebView2 runtime is needed for application startup, which is outside this diagnostic, and is not an additional build gate. Missing or different tools are blockers unless a separately reviewed and authorized, exact-version provisioning procedure is specified. An optional, separately authorized Rust provisioning proposal is `rustup toolchain install 1.100.0 --profile minimal --target x86_64-pc-windows-msvc`; the draft does not run it. No unversioned toolchain updates. Confirm intended token rights as far as independently possible; unexpected credentials or permissions stop the attempt. These checks cannot establish the absence of all runner or service credentials.

## Proposed operations

From official HTTPS sources only, verify approved package and lockfile identities, normal TLS certificate verification and package checksums or integrity, then use `cargo fetch --locked` and, in `apps/desktop`, `node <cached-npm-cli.js> ci --ignore-scripts --strict-peer-deps --engine-strict --no-force --no-legacy-peer-deps --no-audit --no-fund --registry=https://registry.npmjs.org/`. Expected destinations include the crates.io registry/index and its official download endpoints and registry.npmjs.org. Observable unapproved sources, source replacement, insecure transport or TLS and integrity failures stop execution. Ordinary HTTPS redirects in official registry infrastructure that cannot be independently attested are an explicit residual risk: this workflow cannot independently verify or enforce every redirect destination. This is neither a network allowlist nor a sandbox.

Then run only `node node_modules/typescript/bin/tsc --noEmit` and `node node_modules/vite/bin/vite.js build` in `apps/desktop`, followed by `cargo build -p adm-desktop --release --frozen` at the root with the approved MSVC environment. Check only for the existence of `target/release/adm-desktop.exe`; do not launch it. Inspect tracked changes and the planned output locations `apps/desktop/dist/`, `apps/desktop/src-tauri/permissions/autogenerated/`, `apps/desktop/src-tauri/gen/schemas/`, `target/`, approved temporary locations and, if needed, `apps/desktop/node_modules/.vite/`. Unexpected tracked changes or unapproved write locations stop the attempt. These inspections are not tamper-proof.

## Prohibited operations

No dependency version changes, npm lifecycle scripts, arbitrary install scripts, unapproved sources, extra actions, Tauri CLI, MSI or installer, EXE execution, EXE upload or download, artifact upload, releases, PRs, integration, extra tests, automatic retries or reruns. No additional builds or repairs within the attempt. No automatic fallback.

## Explicit residual risks

The runner may have administrator rights. There is no verified inner process, filesystem or network isolation. Dependency code may access temporary runner and service credentials, communicate externally, spawn children or cause external side effects. Checkout files, Git metadata, workflow state, logs, reports and build artifacts can be changed or falsified. The inventory cannot completely monitor Git metadata or runner-external writes. Ordinary official-registry HTTPS redirects are not independently attested. `contents: read` and `persist-credentials: false` do not eliminate all credentials. A fresh VM and `--frozen` are not sandboxes. Organizational scope restrictions are not technical enforcement. Stopping on a detected anomaly does not undo earlier effects. The risks require explicit maintainer acceptance before any execution; this draft does not accept them.

## Evidence classification

Record source and actual workflow revisions, run and job IDs, runner and tool versions, each command and exit code, per-step results, output existence and detected unexpected changes without dumping credentials or private configuration. Results are preliminary diagnostic observations, not trusted quality evidence. They cannot establish isolation or satisfy AC01, AC02, foundation CI, integration, release or product-security gates.

## Execution budget

One attempt in total, including provisioning. No retry, rerun, repair or second build. The workflow rejects a run attempt other than 1 before checkout; this does not prevent a new push from creating a new run. The maintainer and coordinator must externally control and record the authorization and consumption; the branch trigger does not enforce one use.

## Stop conditions

Stop on identity drift, unauthorized versions or sources, missing prerequisites, unexpected credentials or permissions, unexpected writes or observable side effects, inability to confirm zero cost, or an uncertain execution state. Preserve uncertainty; do not retry automatically. The workflow is a draft and its checks do not independently enforce every condition.

## Expiration

The decision, if approved, expires at completion or abortion of the single attempt. It grants no authorization for future work packages.

All system invariants, ADRs, product security, quality, independent review, human acceptance, integration and release requirements remain mandatory. No diagnostic observation waives or replaces them.
